# DreamTwin 关系预演:AI 分身与心理学方案 v0.1

> 本文回答三个核心问题:(1) AI 分身/角色卡片需要哪些信息,才能让大模型**更准确地预测真人行为**;(2) "梦境相遇/关系预演"故事的生成**需不需要 agent 框架** → 结论:演进为**多 Agent 导演式编排**(两个"演员"分身 + 一个"监管"模型),但不引入第三方框架;(3) 从**心理学角度**,演员模型与监管模型各需具备哪些知识(本文重心,见 Part C)。
>
> 配套技术落地见:`DreamTwin_关系预演_技术实现框架_v0.1.md`。

---

## Context(现状与问题)

**产品目标**:让两个用户各自的 AI 分身,在某个场景里预演"如果相遇/相处会怎样",帮用户预判关系发展。**准确性优先,趣味性其次**。

**代码库现状(已核对,非推测)**:
- 已有"梦境相遇"生成框架:[`apps/api/src/modules/content/story.service.ts`](../apps/api/src/modules/content/story.service.ts) —— 单次 Claude 调用(`claude-opus-4-8`),固定 7 帧骨架(scene/you/ta/prop/turn/freeze/reading),结构化输出 `json_schema`,**固定脚本一物两用(few-shot + 失败/无 key/离线兜底)**。
- 人格来自 `Profile.data`([`UserProfile`](../packages/api-types/src/index.ts)),目前是**自由标签**:`personalityKeywords / interests / values / mysticTags / communicationStyle / mbti` 等。`Profile` 与 `Twin` 在 Prisma 里**整体存为 JSONB**(见 [`schema.prisma`](../apps/api/prisma/schema.prisma)),**扩展字段无需迁移**。
- 故事入口:`GET /story/:nodeId`([`content.controller.ts`](../apps/api/src/modules/content/content.controller.ts)),mobile `useDreamStory` 优先 AI、失败回退本地。

**三个关键缺口(决定准确率的根因)**:
1. **只喂了一方人格**。`story.service.ts` 的 `loadPersona` 只加载当前登录用户(「你的分身」);「梦中人/TA」**没有任何卡片**,模型只能凭空虚构 → "两个分身预演"目前其实是"一方 + 想象的陌生人",这是准确率第一缺口。已有的 `RelationshipCounterpartProfile` 类型未被生成链路使用。
2. **人格是扁平标签,缺心理学派生层**。标签很"丰富"但对行为预测是"原始素材",缺少效度高的结构化维度(大五人格、依恋类型、情境 if-then、语气样本)。
3. **没有质量闭环**。单次生成,无人核对"这段戏是否符合两人人设、是否理想化失真"。`/simulation/:nodeId` 仍返回硬编码结果(匹配/预演分析尚未 AI 化)。

本文给出:**(A)** 角色卡片信息模型(在现有自由标签上加心理学派生层)、**(B)** 故事生成架构(从单次 prompt 演进到导演式编排)、**(C)** 演员/监管模型的心理学知识体系。

## Part A:AI 分身角色卡片设计(准确性的核心)

### 设计原则
1. **Show, don't tell**:真实**行为样本/语料**比抽象标签更能提升预测准确性。卡片要"事实 + 证据"并存。
2. **来源分层 + 置信度**:每个派生字段标 `source`(标签/问卷/聊天/访谈/第三方/派生)与 `confidence`;**低置信项不得当事实编故事**——防"看似合理实则失真"。
3. **预测导向,而非展示导向**:字段是给 LLM 做情境决策用的,写成"在 X 情境下倾向 Y",而非堆名词。
4. **加法、不破坏现有结构**:在现有 `UserProfile` 自由标签之上**新增可选** `psychology` 派生层(JSONB,免迁移),老数据零影响。
5. **自由标签 → 心理学派生层**:标签负责"丰富",派生层负责"准确"。派生层可由标签 + 问卷 + 聊天历史自动合成(见技术文档"派生器")。

### 卡片分层(在 `UserProfile` 上的目标形态)
| 层 | 现有承载(`UserProfile`) | 需新增(`psychology` 派生层) | 作用 |
|---|---|---|---|
| L1 基础事实 | `nickname/education/zodiac/bloodType` | — | 锚定合理性 |
| L2 性格特质 | `mbti`(呈现层)、`personalityKeywords` | **bigFive(OCEAN)**、**attachmentStyle 依恋类型** | 行为决策内核 |
| L3 价值观与动机 | `values`、`relationshipIntention` | **dealbreakers 红线** | 决定关键抉择 |
| L4 兴趣与生活方式(趣味来源) | `interests`、`appearanceTags` | — | 故事素材与"梗" |
| L5 行为样本/语料(准确性最大杠杆) | `optionalSignals`、`mysticTags`(部分) | **voiceSamples 语气样本**、情境反应样本 | few-shot,"说话像本人" |
| L6 关系情境倾向 | `communicationStyle` | **conflictStyle、loveLanguages、emotionRegulation** | 直接服务相处预演 |
| L7 if-then 情境签名 | — | **ifThenSignals(CAPS)** | 把特质翻译成可演绎行为 |
| L8 预演约束 | — | 复用 `dealbreakers` + 内容安全 | 防 OOC/越界 |

> 完整字段目录见**附录 A**。所有新增字段**可选**,缺失处按基准率留白。

### 让大模型"更准确预测"的 6 个杠杆
1. **行为样本 few-shot > 抽象标签**:每个分身带 3–5 条真实语气样本(`voiceSamples`)。
2. **字段带置信度/来源**:prompt 明确——低置信项可"不确定/留白",**禁编造重大事实**(延续 `story.service` 现有铁律 5)。
3. **OCEAN 做内核,MBTI 做呈现**:行为决策用大五人格,MBTI 只作用户共鸣层。
4. **依恋类型 + 红线必填级**:这两项对亲密关系情境预测力最强。
5. **情境化渲染**:卡片渲染成 persona 文本时显式写"在 X 情境下倾向 Y",而非只丢标签。
6. **一致性校验闭环**:故事每句台词/决策回查卡片,标 OOC 并重生成(见 Part B / 监管模型)。

## Part B:故事生成架构(从单次 prompt 演进到导演式编排)

### 直接结论:需不需要 agent 框架?
- **需要一个"编排层/导演",但不需要引入第三方 agent 框架,也不需要让分身做自主 tool-calling。** 用**确定性流水线**编排多个 Claude 角色(导演/双分身/监管/叙事),**复用现有 `@anthropic-ai/sdk` 与 NestJS 服务**即可。
- **为什么不停留在单次 prompt**:容易人设漂移、两个人物声音糊在一起、生成中无法纠偏、且当前只喂一方人格。
- **为什么不用自主 agent**:故事需要可控结构(场景→节拍→对戏→校验→成稿),确定性编排比自由发挥更稳;分身不需要工具,只需"按卡片演"。

### 角色与"演员/监管"心智模型
- **演员模型 = 两个分身**(「你的分身」「梦中人」),各拿各自卡片,信息隔离。
- **监管模型 = 导演 + 校验**(同一监管职责两面:导演定场景/节拍,校验抓 OOC/越界并打回)。
- **叙事**:把通过校验的对戏润色成最终 7 帧图文,不参与判定。
- 监管模型承载的心理学知识见 **Part C**。

### 编排管线(目标态)
1. **场景设定**:沿用现有 `SceneTemplate`(雨夜便利店等)+ 节拍骨架;导演按两张卡片挑"最能暴露契合度"的张力点。
2. **逐幕对戏**:两个分身各按自己卡片(含语气样本)产出 you/ta 台词与反应,信息隔离避免"读心"。
3. **一致性 + 安全校验(核心闭环)**:监管按两张卡片逐条判 OOC / 触红线 / 理想化失真,不过则带理由打回重演(重试有上限)。
4. **成稿**:压回固定 7 帧 schema(scene/you/ta/prop/turn/freeze/reading),延续现有结构与 `sanitizeFrames` 校验。
5. **兜底不变**:任一步失败 → 现有固定脚本兜底,前端无感。

### 落地策略(渐进,见技术文档)
- **阶段 0(已存在)**:单次 prompt + 一方人格 + 兜底。
- **阶段 1(本次接入)**:① 卡片心理学派生层(类型 + 渲染器);② **喂两方人格**(修复第一缺口);③ 系统提示升级为"双卡片驱动"。
- **阶段 2**:加入监管/校验一次重生成(可灰度开关,控成本/延迟)。
- **阶段 3**:`/simulation` 接入真实预演分析(契合点/摩擦点评分),替换硬编码。

### 不建议自研通用 agent 框架
做一个**领域专用的 Rehearsal 编排模块**(导演式 pipeline + 卡片渲染 + 质量闭环)即可,比通用 ReAct 更契合"准确性优先的短故事生成",也贴合现有 NestJS + 单次结构化输出的工程现状。

## Part C:心理学知识体系(保证准确率的核心)

> 关键认知:**演员的任务是"像本人一样行动",监管的任务是"判断整段互动像不像真人会发生的事"**——两者需要的心理学知识不同。

### C0. 行为预测的科学前提(决定准确率上限)
1. **人 × 情境交互论(Mischel)**:行为由"情境触发的 if-then 模式"决定,而非固定性格。`内向`预测力弱;`公开场合被否定 → 沉默回避`这种**情境-行为签名(CAPS)**才准。**准确率第一杠杆。**
2. **概率性 + 校准**:真人行为是概率分布;画像薄处**回退人群基准率并表达不确定**,不要自信地编。
3. **反理想化偏差**:LLM 天然把人演得更善解人意、更体面。真实 = 带防御、偏见、误解、口是心非、情绪化。**按住"演得太完美"是监管核心职责。**

### C1. 演员模型(每个分身)需要的知识 —— 用于"像本人一样行动"
| 框架 | 作用 | 备注 |
|---|---|---|
| **大五人格 OCEAN** | 行为决策内核(实证效度最高) | 主引擎 |
| **MBTI** | 用户共鸣/呈现层 | 效度低,**不当**预测内核 |
| **依恋类型**(安全/焦虑/回避/恐惧) | 亲密关系最强预测项:靠近、冲突、吃醋、求安慰、退缩 | 必备 |
| **情绪评价理论(appraisal)** | 同一事件因"如何解读"产生不同情绪 → 决定反应 | 让反应有因果 |
| **动机/价值观(SDT、Schwartz)** | 驱动关键抉择(自主/胜任/联结) | 决定"会不会选这条路" |
| **应对/情绪调节风格** | 压力下问题导向 vs 情绪导向、爆发 vs 压抑 | 张力点关键 |
| **自我呈现/印象管理** | 约会初期"社交面具" vs 私下真实 | 别一上来交底 |
| **if-then 情境签名(CAPS)** | 把以上特质落成"在 X 情境下倾向 Y" | **准确率第一杠杆** |
| **行为样本/语料(few-shot)** | 真人口头禅、用词、语气 | 比任何标签更"像本人" |

### C2. 监管模型(导演/校验)需要的知识 —— 用于"判断真不真并纠偏"
| 知识 | 监管用途 |
|---|---|
| **特质-行为一致性** | 每个动作能否从该人卡片推出?推不出 → 判 OOC 打回 |
| **基准率/合理性** | "真人真会这么做吗?"——揪理想化、戏剧化、超人设"金句" |
| **认知偏差库**(基本归因错误、确认偏差、自利偏差、投射、光环效应) | 主动注入真实的不完美 |
| **依恋配对动力学** | 焦虑×回避 = 追逃循环;安全型稳定对方——判断走向是否合配对规律 |
| **Gottman 关系研究**(四骑士:批评/蔑视/防御/冷战;正负互动比 ~5:1;turning toward) | 判断冲突戏是否真实、预测关系成败 |
| **红线/dealbreaker/安全边界** | 越界即打回(延续现有"低风险、非判决"铁律) |

### C3. 双人关系层(两人合起来才有的动力学,供监管 + `/simulation` 洞察)
- **投资模型(Rusbult)**:满意度 + 替代选择 + 投入 → 承诺,预测关系能否走下去。
- **斯滕伯格爱情三角**(亲密/激情/承诺):刻画两人当前关系形态。
- **冲突风格(Thomas-Kilmann)** + **爱的语言**:具体相处机制。
- **相似性 vs 互补性**:定位契合点与摩擦点(可映射到 `attractionScore/paceScore/riskScore`)。

### C4. 核心洞察
**准确率 = 个体保真 × 互动保真。** 两个各自完美建模的人,若互动动力学(追逃、四骑士、配对规律)不对,整段仍是假的。因此:**个体心理学住在演员模型里,双人/人际动力学住在监管模型里**——这正是"为什么需要监管模型",而不只是两个演员各演各的。

## 准确性 vs 趣味性的平衡(顺序:先不失真,再加戏)
- **准确性(优先)**:语气样本 few-shot、置信度约束、OCEAN 内核、依恋/红线、校验闭环、双卡片信息隔离。
- **趣味性(其次)**:`interests/mysticTags` 提供素材、导演挑有张力的节拍、叙事润色画面感——但不得违背人设。

## 附录 A:角色卡片完整特质目录(★ = 关系预测高权重)

> 约定:每个**派生字段**带 `{ value, source, confidence }`。现有自由标签即原始素材;下表是其上派生/沉淀的结构化全集。映射到 `UserProfile.psychology`(可选,JSONB 免迁移)。

- **A1 基础事实**:年龄、性别、性取向、城市、家乡、职业、学历(`education`)、人生阶段、作息。
- **A2 大五人格 OCEAN**(各 0–100)★:开放性/尽责性/外向性/宜人性/神经质 → `psychology.bigFive`。
- **A3 其他人格模型**:`mbti`(呈现层)、HEXACO 诚实-谦逊、黑暗三联征(风险信号)★、气质 BIS/BAS。
- **A4 依恋与亲密**★:依恋类型(安全/焦虑/回避/恐惧)+ 焦虑/回避维度分、亲密节奏、安全感/独立需求 → `psychology.attachmentStyle`。
- **A5 情绪**:稳定性、表达度、粒度、主导基调、触发点、调节策略(重评/抑制/宣泄/回避)→ `psychology.emotionRegulation`。
- **A6 价值观与动机**★:`values`、Schwartz 排序、SDT 三需求、人生目标、`relationshipIntention`、**dealbreakers 红线**★ → `psychology.dealbreakers`。
- **A7 关系与社交行为**★:冲突风格(竞争/合作/妥协/回避/迁就)、爱的语言(给予&接收)、`communicationStyle`、社交能量、嫉妒/信任倾向、边界感、主动性 → `psychology.conflictStyle / loveLanguages`。
- **A8 兴趣与生活方式**(趣味来源):`interests`、作息、消费、雷区话题、媒体口味、`appearanceTags`。
- **A9 行为样本/语料**★:口头禅、用词、标点/表情习惯、典型句式、情境反应样本(被拒/吵架/开心/紧张/被夸)、历史决策样本 → `psychology.voiceSamples` + `optionalSignals`。
- **A10 if-then 情境签名(CAPS)**★:一组 `IF <情境> THEN <倾向行为>`(如 `IF 对方迟到不解释 THEN 嘴上说没事但冷淡`)→ `psychology.ifThenSignals`。
- **A11 关系史与背景**(隐私敏感、谨慎):过往关系模式、原生家庭影响、重大经历。

> **必填最小集** = A1 基础 + A2 OCEAN + A4 依恋 + A6 红线 + A9 语料 + A10 若干 if-then;其余随标签/问卷/聊天/访谈数据增长由派生器补全,缺失按基准率留白。

## 验证方式
1. **覆盖度自检**:对照 A1–A11,确认每层服务"预测行为"而非仅展示。
2. **走查**:用 2 对真实/虚构画像跑生成链路,人工判断对戏是否符合人设、监管能否抓 OOC。
3. **A/B**:阶段 0(单 prompt 单人格)vs 阶段 1(双卡片+派生层)vs 阶段 2(加监管),人工对"准确性/趣味性"打分。
