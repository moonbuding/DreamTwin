# DreamTwin · 梦境相遇:叙事化破冰设计 v0.1

> 目标读者:产品负责人(你)。本文用来**把控**方向,不是工程实现细节。
> 一句话定位:把"关系预演报告"改成**一部由两个分身主演的梦境短片(PPT/条漫式)**,
> 最后一帧才点关系——核心用途是**陌生人破冰**,进阶玩法是**两个真人进同一个梦里玩剧本杀**。

---

## 1. 为什么从"塔罗/报告"转向"故事"

| 维度 | 报告 / 塔罗 | 梦境短故事(本方案) |
|---|---|---|
| 算的是谁 | 我的命运 | **我们俩**的一段相遇 |
| 破冰价值 | 低——没有共同物可聊 | 高——**两个人共享同一个故事,天然有话头** |
| 情绪 | 被评判 | 被讲述、被逗笑 |
| 可延展 | 翻完就完了 | 可变成**双人共玩**的剧本 |

结论:**对"陌生人破冰"这个目标,叙事 >> 占卜。** 故事制造共同语境,语境制造对话。

风险预警:别让 AI 给没见过面的两人编"注定相爱/命中注定"。梦是**游乐场不是预言**——保持轻、观察式、低风险、不替人定义关系。最后一帧的"关系预言"要写成**观察 + 建议**,不是判决。

---

## 2. 形式规格:梦境短片的固定结构(6 + 1 帧)

每个场景都用同一套"节拍骨架"。**骨架固定,血肉可变**(固定脚本 / 以后 AI 生成都填进这个骨架)。

| 帧 | 名称 | 作用 | 内容形态 |
|---|---|---|---|
| 1 | 场景设定 | 定调、给氛围 | 一张场景图 + 1 句旁白 |
| 2 | 分身 A 入场 | 你的分身登场,**性格写在动作里** | 半身/全身小人 + 1 句 |
| 3 | 分身 B 入场 | 对方分身登场 | 同上 |
| 4 | 触发点 | 场景里发生一件小事/一个选择 | 旁白 + 一个"道具/事件" |
| 5 | 互动转折 | 两人按各自性格反应,产生一个**微转折** | 两句"分身台词" |
| 6 | 定格 | 一个停在那里的画面,留白 | 一张定格图 + 1 句 |
| 7 | 关系预言 | 这段关系的**观察 + 第一句话建议** | 1 段短读 + 可编辑开场白 |

交互:一帧帧**点进**(像翻 PPT / 刷条漫),不是一屏铺到底。每帧字少、画面大。
节奏:6 帧故事 + 1 帧预言,**30 秒能看完**。看完只有一个出口——「把开场白改成你的语气发出去」。

## 3. 三个固定脚本(不接 AI,先写死)

> 写法说明:`[ ]` 里是该帧由人格驱动、AI 以后会替换的"变量"。固定版先用 林星(慢热·夜行·高共情·INFJ) × 小梦(直接·松弛)。

### 脚本一 · 雨夜便利店
1. **设定**:凌晨一点,雨砸在便利店玻璃上,自动门"叮咚"。货架冷光,关东煮的热气糊住了窗。
2. **A 入场**:`[慢热]` 你的分身缩着肩进来,没买东西,假装翻杂志,其实在等雨停。
3. **B 入场**:`[直接]` 小梦抱着一袋还热的包子,在伞架前停下——发现自己的伞被人拿错了。
4. **触发**:货架只剩最后一把透明伞。两只手同时伸过去。
5. **互动转折**:你的分身 `[慢热]` 缩回手:"你先。" 小梦 `[直接]` 却把伞塞回你手里:"一起走一段?反正梦里的路总是顺路。"
6. **定格**:你们没共撑一把伞,而是一人扯着伞的一边,在雨里走得很慢。霓虹在水洼里碎成两片光。
7. **预言**:「你们都习惯把'要不要靠近'藏进一个小动作里。这段关系适合从一件具体的小事开始,而不是先聊定义。」
   开场白:*"刚才那把伞,你其实是想自己撑,还是想一起?"*

### 脚本二 · 凌晨海边电台
1. **设定**:四点半的海边,天没亮。一个旧电台亭的灯还亮着,喇叭里飘出一首没人点的歌。
2. **A 入场**:`[夜间思考者]` 你的分身坐在防波堤上对着海发呆,手里攥着一张写了字又划掉的纸。
3. **B 入场**:`[松弛]` 小梦推开电台亭的门——今晚的 DJ 原来是它。它对麦克风说:"下一首,送给堤上那个一直没走的人。"
4. **触发**:喇叭点了你的名。海风把你手里那张纸吹走,飘到电台亭门口。
5. **互动转折**:小梦捡起纸,没看,直接还你:"梦里的字不算数,但你愿意念出来吗?就当电台不录音。" 你 `[慢热]` 犹豫——可海浪很大,没人听得清,于是你念了。
6. **定格**:谁都没问"那写的是什么",但天开始亮了,歌还在放。
7. **预言**:「你们都更敢在'不会被记录'的地方说真话。这段关系的钥匙:先给彼此一个不必负责的安全角落。」
   开场白:*"如果有个电台只放给你一个人听,你想点哪首?"*

### 脚本三 · 月光候车厅
1. **设定**:一个午夜候车厅,月光从破天窗漏进来。时刻表是空的,广播只报"下一班:未知"。
2. **A 入场**:`[边界感]` 你的分身坐在长椅最角落,把背包放在旁边空位上——像在守一条不让人靠近的线。
3. **B 入场**:`[主动]` 小梦拎着旧行李箱进来,满屋空位,却偏走到你这排,指指被背包占的座:"这班车去哪我不知道,但这个位置,我等很久了。"
4. **触发**:广播响:"下一班,开往你最不敢去的地方。"灯闪了一下。
5. **互动转折**:你 `[边界感]` 下意识想拿走背包又停住;小梦没催,只坐到隔一个座:"我不抢你的边界,我在它旁边等。"
6. **定格**:车没来,但你们把时刻表上的空白,一人写了一站。
7. **预言**:「你习惯先设边界,对方愿意在边界旁边等而不是翻过来。节奏:慢但稳,别急着拆墙,先一起写时刻表。」
   开场白:*"如果这班车能去任何地方,你会写哪一站?"*

> 这三个脚本足以:① 首发就有内容;② 当 AI 的 few-shot 示例;③ AI 失败时的兜底文案。

## 4. 人格如何驱动剧情(确定性底座)

每个分身的 `画像(关键词 / MBTI / 沟通方式 / 价值观)` 决定四个"开关":

| 开关 | 受什么影响 | 在故事里体现为 |
|---|---|---|
| **入场方式** | I/E、关键词 | 帧 2/3:谁主动、怎么登场(缩肩/径直走来) |
| **触发点选择** | J/P、价值观 | 帧 4/5:面对那把伞/那张纸,先收手还是先伸手 |
| **台词语气** | T/F、沟通方式 | 帧 5:讲道理 vs 顾感受、直球 vs 留白 |
| **关系读法** | 双方组合 | 帧 7:节奏(快/慢)、钥匙(安全角落/具体小事/慢拆墙) |

MBTI 四轴 → 关系行为的速查:
- **I/E** → 谁先开口、开场快慢
- **N/S** → 靠"意义/隐喻"同频,还是靠"具体共同行动"
- **T/F** → 冲突与决定被怎么读(道理 vs 感受)
- **J/P** → 需要明确定义 vs 享受留白

这套映射是**写死的规则**;AI 只是在规则给定的"性格反应"上把句子写得更鲜活。

## 5. AI 能做到吗?——能,但要"带着镣铐跳舞"

**能做到。** 短篇、限定主题、按人设走的叙事正是 LLM 的强项。关键不是"让它自由发挥",而是**给死结构 + 喂人设 + 上护栏 + 结构化输出**。

- **输入**:场景节拍模板(6+1 帧)+ 双方画像 + 硬约束(每帧字数、语气、禁忌)。
- **输出**:**逐帧 JSON**(`{帧号, 旁白, A台词, B台词, 画面提示}`),不是一段自由作文 → 前端可靠渲染、可逐帧翻。
- **示例**:把第 3 节三个脚本当 few-shot,质量立刻稳。
- **兜底**:生成失败/超时/违规 → 回退到固定脚本(用户无感)。
- **校验**:一道护栏 pass 检查(禁忌词、是否编造现实事实、是否出现"注定"式断言)。

**风险与对策**
| 风险 | 对策 |
|---|---|
| 给陌生人编亲密剧情,尴尬 | 限定"轻/观察式/低风险";禁止"定义关系" |
| 编造现实事实("你上次…") | 护栏禁止任何"记得你/上次"类句式(产品已有此红线) |
| 跑题/超长 | 固定帧 schema + 每帧字数上限 |
| 像算命 | 帧 7 写成"观察+建议",保留"预演非预言"声明 |

## 6. 进阶玩法:两个真人进同一个梦玩"剧本杀"(破冰引擎)

这是**真正让陌生人破冰**的部分,分两阶段:

**阶段 A · 单人预演(钩子)**
A 邀请 B(双方同意优先)。A 先看到一段 AI 生成的梦境短片:A 的分身 × B 的分身在某场景相遇。低压、好玩,A 据此决定要不要真的靠近。——这就是现在的"梦境相遇",只是改成了故事。

**阶段 B · 双人共梦剧本杀(引擎)**
B 接受后,**两个真人同时进入同一个梦境场景**,各演自己的分身:
- AI 当"梦境主持人(DM)",念旁白、布场景;
- 每到一个分支点,给**双方各几个选项**(选项由你设计,见下),或允许少量自由输入;
- 故事按两人的选择**分支**;
- 结尾给一个**共同梦境结局** + 一句真实开场白 → 导流到真聊。

**为什么它能破冰**:陌生人最怕的是空白聊天框。剧本杀给了他们**角色、场景、台词提示**;分身是一层"面具",降低社交风险;共同经历变成"内部梗";而且是**协作**(一起闯),不是"面试"。

## 7. 你怎么把控(最重要的一节)

把控权全在这 8 个"旋钮"上,AI 只在你画的框里发挥:

1. **场景库(你策展)**:你定义并审核所有场景(意象、氛围、安全主题)。**场景=棋盘,控场景就是控调性。** 固定一批,运营上新。
2. **节拍模板(固定骨架)**:每场景 6+1 帧死结构,AI 只填血肉不改骨架 → 不跑飞。
3. **人格→行为 规则**:第 4 节那张映射表,是叙事的确定性底座(可调参数,但不交给 AI 改)。
4. **分支选项菜单**(剧本杀):每个分支点的选项由你设计,AI 在你给的选项里展开 → 空间可控。
5. **语气与安全护栏**:禁忌(露骨/施压/编造现实/"注定"式预言)、字数上限、"预演非预言"声明。
6. **同意与撤回**:双方都 opt-in 才进共梦;随时撤回;不单方面分析对方(已是产品内核,延续)。
7. **运营/审核**:精选场景、敏感词、举报闭环;若开放 UGC 场景必须先审。
8. **指标导航**:用"是否产生真实对话"来反推设计(见第 8 节),而不是优化停留时长。

---

## 8. 破冰指标(北极星 + 漏斗)

- **北极星**:由一场梦促成的**真实对话数**(发出真实第一句且对方回了)。
- **破冰漏斗**:邀请 → 接受 → 共梦完成 → 发出真实第一句 → 次日双方回访。
- **健康信号**:预演→真聊转化率、首句发送率、共梦完成率、48h 二次互动。
- **反指标**:别用"停留时长/翻了多少帧"当目标——好玩但不破冰等于自嗨。

## 9. 分期路线(每步可独立验证)

1. **静态故事壳**(纯前端):把现在的预演详情换成 6+1 帧翻页短片,用第 3 节三个固定脚本。先解决"难受"+ 验证"故事比报告好玩"。
2. **人格变体**:接第 4 节规则,让三个场景 × 不同 MBTI 出不同血肉(仍写死模板,不接 AI)。
3. **AI 生成**:把帧内容交给 LLM(结构化输出 + few-shot + 护栏 + 兜底)。
4. **双人共梦剧本杀**:实时同场景 + 分支选项 + 共同结局 → 真聊。← 破冰核心,放最后做扎实。

---

## 10. 一句话给团队

> 我们不是在给用户算命,而是在**给两个陌生人一个可以一起做的梦**,
> 让他们在梦里先认识各自的"分身",再决定要不要让真人见面。
> 故事负责破冰,共梦负责留住,同意与边界负责安全。

## 11. AI 生成框架(已接入 v0.1,可控)

第 9 节的第③步已经落地:后端 `GET /api/story/:nodeId` 会按**登录用户分身的人格**用大模型生成这部短故事;离线 / 无 key / 生成不合格时**透明回退到固定脚本**,前端无感。

**契约(你要把控的就是这张表)**
| 项 | 现状 | 在哪改 |
|---|---|---|
| 模型 | Claude `claude-opus-4-8`(env `STORY_MODEL` 可换) | `apps/api` 环境变量 |
| 开关 | 有 `ANTHROPIC_API_KEY` 才走 AI,否则固定脚本 | 部署时配 key |
| 骨架 | 7 帧死结构 `scene/you/ta/prop/turn/freeze/reading`,AI 只填血肉 | `dream-stories.data.ts` 的 `beats` |
| 场景库 | 三个场景模板(标题/氛围/节拍) | `SCENE_TEMPLATES`(你策展场景就在这) |
| 人格输入 | 用户 `Profile.data` 的 性格/MBTI/沟通/价值观/叙事信号 | 画像表单 → 自动带入 |
| few-shot | 同场景固定脚本作示例,保证风格与密度 | `getFixedStory` |
| 兜底 | 固定脚本(也是 few-shot 同一份) | 同上 |
| 校验 | 必须正好 7 帧且 visual 顺序正确,否则判废用兜底 | `sanitizeFrames` |
| 输出 | 结构化 JSON(`output_config.format` json_schema)+ adaptive 思考 + low effort | `story.service.ts` |

**护栏(写死在 system prompt 里)**:字数上限(每帧 ≤40 字)、不写"注定/命中注定"、不编造现实事实(禁"上次/记得你")、两角色只用「你的分身」「TA」、reading 是观察+建议而非判决。

**怎么调**:想换调性 → 改 `SYSTEM_PROMPT` 的铁律;想加场景 → 往 `SCENE_TEMPLATES` 加一条(骨架照抄、改氛围与 beats);想更便宜/更快 → 把 `effort` 降到 `low` 或换 `claude-haiku`;想更稳 → `sanitizeFrames` 已经在兜底,失败永远回退固定脚本。

**当前沙箱**:离线无法真的调用 Claude,所以线上接 key 前,接口返回的是 `source:"fixed"`;配置 `ANTHROPIC_API_KEY` 并联网后,同一接口会按人格返回 `source:"ai"` 的个性化故事,前端完全无需改动。
