# DreamTwin 需求池 v0.1

> 文档状态：开发 Backlog 基准版
> 当前阶段：PRD 已完成，下一步进入技术方案
> 上游文档：`doc/DreamTwin_产品说明书_v0.1.md`、`doc/DreamTwin_MVP原型方案_v0.1.md`、`doc/DreamTwin_路演Demo方案_v0.1.md`、`doc/DreamTwin_PRD_v0.1.md`

## 1. 需求池目标

本需求池把 DreamTwin PRD 拆成可开发、可验收、可进入技术方案的 Backlog。

当前目标不是做报名材料，也不是一次性拼 Demo，而是为 DreamTwin 的真实 App 落地建立第一版执行清单。

第一版实现建议继续采用移动端 Web，但体验标准按 App 规划。

P0 标准锁定为：

> 视觉震撼优先，同时尽力跑通完整路径。

### 1.1 核心口径校准

当前 Backlog 的核心对象从“关系预告片”校准为 **AI 双人关系预演模拟**。

第一版仍然可以用短片化、分幕化方式展示，但需求拆解必须服务更深的产品内核：

- 模拟双方画像。
- 模拟相遇事件。
- 模拟可能对话和行为。
- 模拟关系发展路径。
- 输出恋爱可能、冲突风险、不好走向和建议动作。

“关系预告片”只表示展示包装，不再作为核心数据资产命名。

也就是说，第一版不能只是静态页面。它必须让用户和路演观众感到：

- DreamTwin 有梦境空间。
- AI 分身有存在感。
- 关系预演模拟不是普通文案卡片。
- 梦境节点可以被点击、进入、等待、打开。
- 最终可以走向真实聊天入口。

## 2. 优先级定义

### P0：第一版必须完成

P0 是移动端 Web MVP / Demo 的最小可演示闭环。

P0 需求必须满足：

- 能进入后续技术方案。
- 能被拆成页面、组件、状态或数据任务。
- 能服务完整演示路径。
- 视觉完成度不能低到像静态草稿。
- 不依赖真实后端、真实匹配或 AI 实时生成。

### P1：增强互动感和路演震撼感

P1 是在 P0 闭环基础上提升体验张力的需求。

P1 需求主要服务：

- 动效。
- 转场。
- 视觉节奏。
- 路演稳定性。
- 关系预演模拟的情绪和关系发展递进。

P1 不应该抢走 P0 的核心路径职责。

### P2：后续 App 化储备

P2 是未来真实产品化阶段的需求。

P2 不进入第一版移动端 Web MVP 的开发范围，除非后续重新调整路线。

P2 主要包括：

- 登录注册。
- 真实匹配。
- AI 实时生成。
- 聊天后端。
- 推送。
- 审核。
- 数据分析。
- Native App 迁移。

## 4. P0 需求

### DT-P0-001：移动端 Web App-grade 壳层

- 需求 ID：`DT-P0-001`
- 优先级：P0
- 所属模块：基础体验
- 用户目标：用户打开 Demo 时感到这是一个 App 雏形，而不是普通网页。
- 需求描述：搭建移动端 Web 单页体验壳层，按 App 比例、沉浸式首屏、固定底层状态管理和页面切换来组织体验。
- 验收标准：
  - 页面在移动端宽度下优先展示，适合手机竖屏演示。
  - 首屏不出现明显浏览器网页感或文档感。
  - 页面切换不刷新浏览器。
  - 所有核心页面能在同一条演示路径中连续访问。
  - UI 不出现文本溢出、遮挡或明显布局跳动。
- 依赖关系：无。
- Demo 价值：决定第一眼是否像一个可继续长成 App 的产品。

### DT-P0-002：静态 Demo 数据

- 需求 ID：`DT-P0-002`
- 优先级：P0
- 所属模块：数据基础
- 用户目标：用户能看到完整、稳定、可信的示例内容。
- 需求描述：基于 PRD 中的 `UserProfile`、`TwinProjection`、`DreamNode`、`RelationshipSimulation` 建立第一版静态 Demo 数据。前端类型和状态字段统一使用 `simulation` 语义。
- 验收标准：
  - 至少包含 1 个用户画像。
  - 至少包含 1 个 AI 分身抽象投影。
  - 必须包含 3 个梦境节点。
  - 每个梦境节点必须绑定 1 条关系预演模拟。
  - 每条关系预演模拟必须包含可能对话、关系发展路径、恋爱可能、冲突风险、不好走向和建议动作。
  - 数据能支持未查看、已查看、等待对方入梦、梦境门打开等状态。
  - 不接入真实匹配、不接入 AI 实时生成。
- 依赖关系：PRD 数据结构。
- Demo 价值：保证演示不会依赖临场输入质量或网络生成结果。

### DT-P0-003：欢迎 / 产品解释页

- 需求 ID：`DT-P0-003`
- 优先级：P0
- 所属模块：首次体验
- 用户目标：用户在 30 秒内理解 DreamTwin 不是普通社交，也不是 AI 陪伴。
- 需求描述：实现欢迎页，解释 DreamTwin 的核心机制：先由 AI 分身预演关系，再由用户决定是否进入真实互动。
- 验收标准：
  - 页面明确表达“AI 关系预演社交”。
  - 页面能引导用户开始创建 AI 分身。
  - 不把产品说成 AI 陪聊、虚拟恋人、游戏或玄学占卜。
  - 视觉需要有梦境感和关系开端感。
  - 点击主按钮后进入 AI 分身创建页。
- 依赖关系：`DT-P0-001`。
- Demo 价值：建立产品心智，避免路演观众误解方向。

### DT-P0-004：AI 分身创建页

- 需求 ID：`DT-P0-004`
- 优先级：P0
- 所属模块：AI 分身
- 用户目标：用户能输入少量信息，感觉自己的关系偏好正在被理解。
- 需求描述：实现 AI 分身创建页，收集昵称、人格关键词、关系倾向、兴趣线索和可选依据。
- 验收标准：
  - 页面至少支持输入昵称。
  - 页面至少支持选择或输入人格关键词。
  - 页面至少支持选择关系倾向。
  - 页面说明 AI 分身用于关系预演，不是替用户聊天。
  - 主按钮能进入 AI 分身生成页。
  - 表单可以使用 Demo 默认值，避免路演输入耗时过长。
- 依赖关系：`DT-P0-001`。
- Demo 价值：让用户参与创建，从旁观变成进入体验。

### DT-P0-005：AI 分身生成与抽象投影

- 需求 ID：`DT-P0-005`
- 优先级：P0
- 所属模块：AI 分身
- 用户目标：用户看到一个有存在感的人格投影，而不是普通头像或聊天机器人。
- 需求描述：生成 AI 分身摘要和抽象投影预览，用昵称、人格摘要、颜色、光影、轮廓和关键词标签表达分身。
- 验收标准：
  - 展示 AI 分身昵称。
  - 展示人格摘要。
  - 展示关键词标签。
  - 展示抽象投影视觉。
  - 不出现五官、身体、服装、换装、等级或养成属性。
  - 页面能继续进入昨夜梦境日志页。
- 依赖关系：`DT-P0-002`、`DT-P0-004`。
- Demo 价值：形成第一个震撼点，让观众感到 AI 分身存在。

### DT-P0-006：昨夜梦境日志页

- 需求 ID：`DT-P0-006`
- 优先级：P0
- 所属模块：梦境日志
- 用户目标：用户能理解每天打开 DreamTwin 是为了查看昨夜梦境日志。
- 需求描述：实现昨夜梦境日志页，作为进入梦境星图和关系预告片的首页。
- 验收标准：
  - 页面标题明确为昨夜梦境日志。
  - 页面出现 AI 分身简短摘要。
  - 页面出现 3 个关系机会的概览。
  - 页面能自然引出梦境星图。
  - 文案表达“这些是关系可能性的预演”，不是聊天记录。
- 依赖关系：`DT-P0-002`、`DT-P0-005`。
- Demo 价值：建立日常使用习惯和产品主场景。

### DT-P0-007：梦境星图 3 个节点

- 需求 ID：`DT-P0-007`
- 优先级：P0
- 所属模块：梦境星图
- 用户目标：用户能通过点击梦境节点进入不同关系预告片。
- 需求描述：在昨夜梦境日志页中实现轻量梦境星图，展示 3 个梦境节点，并让每个节点可点击。
- 验收标准：
  - 梦境星图必须展示 3 个节点。
  - 每个节点必须对应一条关系预告片。
  - 节点至少支持未查看、已查看、等待对方入梦、梦境门打开状态。
  - 点击节点后进入关系预告片详情页。
  - 不支持自由探索、路径移动、地图闯关、附近的人或真实地理位置。
- 依赖关系：`DT-P0-002`、`DT-P0-006`。
- Demo 价值：形成 Demo 主舞台，让互动感不只停留在页面跳转。

### DT-P0-008：关系预演模拟详情页

- 需求 ID：`DT-P0-008`
- 优先级：P0
- 所属模块：关系预演模拟
- 用户目标：用户能看到 AI 对两个人相遇、对话、行为和关系发展的模拟，并判断是否想进入。
- 需求描述：实现关系预演模拟详情页，展示梦境标题、对方人格投影、双方画像建模、相遇事件、可能对话、关系发展路径、恋爱可能、冲突风险、不好走向、建议动作和当前节点状态。
- 验收标准：
  - 页面展示当前梦境节点状态。
  - 页面展示对方不是完整身份资料，而是关系预演中的人格投影。
  - 页面至少展示相遇场景、可能对话、行为预演、关系发展路径和匹配依据。
  - 页面必须展示恋爱可能和不好的走向，不能只展示正向结果。
  - 页面提供“想进入这个梦境”的主操作。
  - 页面提供返回梦境星图的路径。
- 依赖关系：`DT-P0-002`、`DT-P0-007`。
- Demo 价值：让“这段关系真的可能开始”的感觉成立。

### DT-P0-009：想进入梦境操作

- 需求 ID：`DT-P0-009`
- 优先级：P0
- 所属模块：关系确认
- 用户目标：用户能明确表达自己愿意让这段预演进入真实关系尝试。
- 需求描述：实现“想进入这个梦境”的操作，将当前节点从已查看或未查看推进到等待对方入梦状态。
- 验收标准：
  - 点击主按钮后进入等待对方入梦页。
  - 当前节点状态更新为等待对方入梦。
  - 页面反馈必须明确：用户不是在和 AI 聊天，而是在等待真实对方确认。
  - 不出现 AI 代替用户发送消息的表达。
- 依赖关系：`DT-P0-008`。
- Demo 价值：把关系预演模拟从观看内容变成真实关系动作。

### DT-P0-010：等待对方入梦页

- 需求 ID：`DT-P0-010`
- 优先级：P0
- 所属模块：关系确认
- 用户目标：用户知道自己已经发起兴趣，接下来等待对方也愿意进入。
- 需求描述：实现等待对方入梦页，展示当前节点等待态、等待文案和对方确认前的限制。
- 验收标准：
  - 页面明确显示等待对方入梦。
  - 页面展示当前梦境节点进入等待态。
  - 页面说明只有双方确认后才打开真实聊天入口。
  - 页面可以通过演示操作推进到梦境门打开态。
  - 不展示真实聊天输入框。
- 依赖关系：`DT-P0-009`。
- Demo 价值：体现 DreamTwin 的双向关系门槛，区别于普通滑卡和 AI 陪聊。

### DT-P0-011：梦境门打开页

- 需求 ID：`DT-P0-011`
- 优先级：P0
- 所属模块：双向梦境门
- 用户目标：用户感到双方确认后关系真的打开了。
- 需求描述：实现梦境门打开页，展示节点打开态、双方已确认文案和进入真实聊天的入口。
- 验收标准：
  - 页面明确显示梦境门已打开。
  - 当前节点状态更新为梦境门打开。
  - 页面展示双方确认的关系反馈。
  - 页面提供进入真实聊天的主按钮。
  - 不把梦境门表现成游戏关卡奖励。
- 依赖关系：`DT-P0-010`。
- Demo 价值：形成演示高潮，让关系转化发生在观众眼前。

### DT-P0-012：真实聊天入口页

- 需求 ID：`DT-P0-012`
- 优先级：P0
- 所属模块：真实互动
- 用户目标：用户理解 AI 预演结束后，真实的人与人互动才开始。
- 需求描述：实现真实聊天入口页，展示聊天开始前的引导和第一句建议，但不开发完整聊天后端。
- 验收标准：
  - 页面明确表达“现在由你自己开始真实聊天”。
  - 页面可以展示建议开场白。
  - 页面不展示 AI 自动代聊能力。
  - 页面不需要真实消息收发后端。
  - 页面能作为完整演示路径终点。
- 依赖关系：`DT-P0-011`。
- Demo 价值：把 DreamTwin 从 AI 预演落到真实关系，而不是停在内容消费。

### DT-P0-013：P0 状态流转

- 需求 ID：`DT-P0-013`
- 优先级：P0
- 所属模块：状态管理
- 用户目标：用户在演示中能看到节点状态连续变化，而不是每页互不相关。
- 需求描述：建立第一版本地状态流转，支撑梦境节点从未查看到已查看、等待对方入梦、梦境门打开的变化。
- 验收标准：
  - 点击节点后能标记为已查看。
  - 点击想进入后能标记为等待对方入梦。
  - 演示推进后能标记为梦境门打开。
  - 从详情页返回星图后能看到节点状态变化。
  - 状态可以存在本地内存，不要求持久化。
- 依赖关系：`DT-P0-007`、`DT-P0-008`、`DT-P0-009`、`DT-P0-010`、`DT-P0-011`。
- Demo 价值：让梦境星图成为真实主舞台，而不是装饰背景。

## 5. P1 需求

### DT-P1-001：梦境星图节点动效

- 需求 ID：`DT-P1-001`
- 优先级：P1
- 所属模块：梦境星图
- 用户目标：用户能感到梦境节点是活的、可进入的。
- 需求描述：为星图节点增加轻量动效，包括呼吸、悬浮、选中、打开等状态表现。
- 验收标准：
  - 节点未查看和已查看状态有视觉差异。
  - 等待态有持续但克制的反馈。
  - 打开态有明显的关系门打开感。
  - 动效不导致性能卡顿。
- 依赖关系：`DT-P0-007`、`DT-P0-013`。
- Demo 价值：增强主舞台的路演吸引力。

### DT-P1-002：抽象投影光影动效

- 需求 ID：`DT-P1-002`
- 优先级：P1
- 所属模块：AI 分身
- 用户目标：用户感到 AI 分身是人格投影，而不是静态图标。
- 需求描述：为抽象投影增加光影、粒子、轮廓或渐变层次变化。
- 验收标准：
  - 动效服务人格气质表达。
  - 不出现可养成角色、虚拟伴侣或换装感。
  - 动效在生成页和日志页保持一致。
- 依赖关系：`DT-P0-005`、`DT-P0-006`。
- Demo 价值：强化 AI 分身存在感。

### DT-P1-003：关键页面转场

- 需求 ID：`DT-P1-003`
- 优先级：P1
- 所属模块：交互体验
- 用户目标：用户在路径推进时感到体验连续、沉浸。
- 需求描述：为关键路径增加转场：创建分身到生成页、生成页到星图、星图到详情、等待到打开。
- 验收标准：
  - 转场方向符合路径推进。
  - 转场时长克制，不拖慢路演节奏。
  - 转场不遮挡核心文案。
  - 返回路径不造成状态错乱。
- 依赖关系：P0 完整路径。
- Demo 价值：让 Demo 像 App，而不是幻灯片。

### DT-P1-004：节点状态变化表现

- 需求 ID：`DT-P1-004`
- 优先级：P1
- 所属模块：梦境星图
- 用户目标：用户能一眼看懂节点从预告片变成等待，再变成打开。
- 需求描述：强化梦境节点状态视觉，包括颜色、亮度、标签、连接线或光门效果。
- 验收标准：
  - 未查看、已查看、等待、打开四种状态可区分。
  - 状态表现不依赖长说明文字。
  - 不误导用户以为可以自由地图探索。
- 依赖关系：`DT-P0-013`。
- Demo 价值：让核心机制通过视觉直接被理解。

### DT-P1-005：关系预演模拟内容节奏

- 需求 ID：`DT-P1-005`
- 优先级：P1
- 所属模块：关系预演模拟
- 用户目标：用户不是读资料，而是在观看一段由 AI 推演出的双人关系发展。
- 需求描述：优化关系预演模拟详情页的信息呈现节奏，把双方建模、相遇事件、可能对话、关系发展、恋爱可能、风险和进入动作组织成短片感体验。
- 验收标准：
  - 内容不是普通资料卡片堆叠。
  - 第一屏能建立关系氛围。
  - 主操作出现时用户已经理解为什么想进入。
  - 文案不滑向玄学或虚假承诺。
- 依赖关系：`DT-P0-008`。
- Demo 价值：提高“关系真的可能开始”的说服力。

### DT-P1-006：路演稳定演示模式

- 需求 ID：`DT-P1-006`
- 优先级：P1
- 所属模块：演示稳定性
- 用户目标：演示者能在 3-5 分钟内稳定跑完整个路径。
- 需求描述：为 Demo 准备稳定路径，减少输入、网络、加载或状态异常对路演的影响。
- 验收标准：
  - 支持使用默认 Demo 数据直接演示。
  - 支持从头跑完整路径。
  - 演示过程中不依赖真实接口。
  - 刷新后可以重新开始演示。
- 依赖关系：`DT-P0-002`、P0 完整路径。
- Demo 价值：降低现场风险。

### DT-P1-007：首屏沉浸视觉完成度

- 需求 ID：`DT-P1-007`
- 优先级：P1
- 所属模块：视觉体验
- 用户目标：用户一打开就感到 DreamTwin 有独特产品气质。
- 需求描述：提升欢迎页和首个关键画面的视觉完成度，建立梦境、人格投影和关系预演的组合感。
- 验收标准：
  - 首屏不只是文字解释。
  - 视觉和文案共同表达产品定位。
  - 不使用过度游戏化或玄学化表达。
- 依赖关系：`DT-P0-003`。
- Demo 价值：提高 30 秒理解效率和第一印象。

### DT-P1-008：移动端交互细节打磨

- 需求 ID：`DT-P1-008`
- 优先级：P1
- 所属模块：交互体验
- 用户目标：用户感觉操作顺滑、按钮明确、反馈及时。
- 需求描述：打磨按钮反馈、触控区域、加载反馈、返回路径和页面滚动体验。
- 验收标准：
  - 主按钮触控区域足够清晰。
  - 加载和等待状态不空白。
  - 返回路径不打断演示。
  - 长内容在手机屏幕中可读。
- 依赖关系：P0 完整路径。
- Demo 价值：让产品从“能看”接近“能用”。

## 6. P2 需求

### DT-P2-001：登录注册

- 需求 ID：`DT-P2-001`
- 优先级：P2
- 所属模块：账号系统
- 用户目标：用户能拥有稳定账号和个人资料。
- 需求描述：后续实现手机号、邮箱或第三方登录注册。
- 验收标准：
  - 支持创建和恢复用户账号。
  - 支持绑定用户资料。
  - 不进入第一版 Demo。
- 依赖关系：技术方案后续版本。
- Demo 价值：无直接路演价值，服务真实 App 留存。

### DT-P2-002：真实匹配系统

- 需求 ID：`DT-P2-002`
- 优先级：P2
- 所属模块：匹配系统
- 用户目标：用户能收到来自真实用户池的关系预告片。
- 需求描述：后续基于画像、兴趣、关系倾向和行为信号生成候选关系。
- 验收标准：
  - 能从真实用户池生成候选。
  - 能避免不合适或重复推荐。

- Demo 价值：服务后续市场化，不作为 P0 前提。

### DT-P2-003：AI 实时生成

- 需求 ID：`DT-P2-003`
- 优先级：P2
- 所属模块：AI 生成
- 用户目标：用户获得基于真实双方画像生成的关系预告片。
- 需求描述：后续接入 AI 生成能力，生成分身摘要、梦境节点和关系预告片。
- 验收标准：

### DT-P2-004：聊天后端

## 7. P0 依赖顺序

建议后续技术方案按以下顺序拆解：

1. `DT-P0-001` 移动端 Web App-grade 壳层
2. `DT-P0-002` 静态 Demo 数据
3. `DT-P0-003` 欢迎 / 产品解释页
4. `DT-P0-004` AI 分身创建页
5. `DT-P0-005` AI 分身生成与抽象投影
6. `DT-P0-006` 昨夜梦境日志页
7. `DT-P0-007` 梦境星图 3 个节点
8. `DT-P0-008` 关系预告片详情页
9. `DT-P0-009` 想进入梦境操作
10. `DT-P0-010` 等待对方入梦页
11. `DT-P0-011` 梦境门打开页
12. `DT-P0-012` 真实聊天入口页
13. `DT-P0-013` P0 状态流转

实际开发时，`DT-P0-013` 可以与页面开发并行推进，但验收必须覆盖完整状态闭环。

## 8. P0 验收总标准

P0 完成后，DreamTwin 第一版移动端 Web MVP / Demo 必须满足：

- 用户能从欢迎页开始创建 AI 分身。
- 用户能看到 AI 分身抽象投影。
- 用户能进入昨夜梦境日志。
- 用户能看到梦境星图中的 3 个梦境节点。
- 用户能点击节点查看关系预告片。
- 用户能选择想进入某个梦境。
- 用户能看到该节点进入等待对方入梦状态。
- 用户能看到梦境门打开状态。
- 用户能进入真实聊天入口页。
- 观众能在 30 秒内理解 DreamTwin 是 AI 关系预演社交。
- 观众不会把 DreamTwin 误解为 AI 陪伴、游戏、地图探索或虚拟角色养成。

## 9. 当前不进入开发的内容

以下内容不进入 P0 或 P1：

- 真实登录注册。
- 真实用户匹配。
- 真实聊天后端。
- AI 实时生成关系预告片。
- 真实地图。
- 可走地图。
- 附近的人。
- 角色养成。
- 换装。
- 虚拟伴侣能力。
- 付费系统。
- 审核后台。
- 推荐算法后台。

这些能力可以作为后续 App 化储备，但不能干扰第一版 MVP / Demo 的聚焦。
